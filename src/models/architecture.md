# src/models/

The model catalog: context limits, prices, modalities and reasoning options come from models.dev, not from code (the image-generation models are the one exception: a curated table).

| File                | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `catalog-shards.ts` | Pure: `CATALOG_PROVIDERS` (google, openai, anthropic, openrouter), the per-provider keep rule (gemini-3+, gpt-5+, claude-5+, text-output OpenRouter), the field list, `buildShards`, `isShard`.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `catalog-cache.ts`  | Downloads `models.dev/api.json`, filters it into one shard per provider (`<cache>/<provider>/models.json`) plus `meta.json` (written last) and drops the payload; the full file is never saved. Only `meta.json` is read at import, `getShardModels(provider)` reads a shard on first use. Cache folder: `<home>/catalog/` (or the `catalog_cache_dir` setting). Stale-while-revalidate: an expired catalog is served at once and refreshed in the background (8 s timeout, 10 min backoff after a failure); only a cold start waits. the `catalog_refresh: "off"` setting stops automatic refreshes. |
| `catalog.ts`        | Lookups (`getModelFromCatalog`), `registerModel`, thinking validation (`validateModelThinking`, which throws `ThinkingLevelError`, a one-line `ConfigError`), and the exported `GOOGLE_/OPENAI_/ANTHROPIC_/OPENROUTER_MODELS` lazy arrays (Proxies over the cached list: nothing is read until first use).                                                                                                                                                                                                                                                                                            |
| `image-models.ts`   | The curated table of supported image-generation models (Google `gemini-nano-banana-2.1`, `gemini-3.1-flash-lite-image`; OpenAI `gpt-image-2.5/2.6` sunburst and flare): aspect ratios, resolution tiers or size rules, quality, formats, reference-image limits, thinking levels, limits and prices. `listImageModels`, `getImageModel`, `unsupportedImageModelReason`. Not derived from models.dev.                                                                                                                                                                                                  |

## Invariants

- `image-models.ts` holds only facts the provider states (a fact it does not state is left out). Only image-generation models belong there; Search grounding is never used. Re-check every number against the provider's pages when a model is added or a price changes.
- Never hand-edit the cache files (`<provider>/models.json`, `meta.json`); register custom models with `registerModel()`. Verified modality fixes go in `MODALITY_OVERRIDES`.
- The global bare-id fallback applies to first-class providers and explicit bare-id lookups only. A custom prefix never borrows another provider's price or modalities: unknown stays unknown.
- A payload that is not a catalog (fewer than 3 providers with models) never overwrites the cache.
- Do not keep static copies of catalog data; use the lookups or the update listener.
- A model outside the kept series (gemini-2, gpt-4, claude-4, other providers) is unknown on purpose. `meta.json` is the commit marker: shards are written first. A `models.dev.json` left by a release before 0.6.8 is never read and is removed by the next successful refresh.
- Keep the rule table in `catalog-shards.ts` the only place that says which models are kept; adding a catalog provider means a `CATALOG_PROVIDERS` entry, a `KEEP` rule and a `PROVIDER_ALIASES` entry.
- With `setModels` set, the catalog is filtered when it is read (`getShardModels` in `catalog.ts`, memoized and dropped on `onModelsChange`): the cache files are never rewritten, because several processes may share a home.
